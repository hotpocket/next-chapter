# next-chapter

Workspace for the Next Chapter admissions project. `course/` mirrors the
pre-course curriculum (sections 0–9; section 9 is the project spec) — reference
only, never published. `config-history.md` documents the AI workflow this
project is built with; it ships with the submission so the reviewer can
interpret the prompt history. **This repo is public.** The project itself
(idea TBD) will be built here; session recaps and their prompts publish with it.

## Session conduct

Session-start orientation is injected by the global `SessionStart` router
(`~/bin/claude-orient`, mirrored in-tree at `.claude/bin/claude-orient`), which
runs this repo's `scripts/session-start.sh`:
latest recap pointer + open-todo count. Go deeper on demand — read the recap body
in `vault/sessions/` or open `vault/todos/next-chapter.md`.

**Vault access is file-first.** Use `scripts/vault-digest` for cheap reads —
grep/awk over note frontmatter, no Obsidian app/CLI/GUI, safe across parallel
sessions:
- `scripts/vault-digest summaries [subdir]` — one-line gist per note (Level 0).
- `scripts/vault-digest type <t>` / `concern <c>` — filter by frontmatter.
- `scripts/vault-digest recap` / `todos` / `backlinks <note>` / `search <q>`.
Read a full note body (Level 2) only after a summary points you to it. The
`/vault` skill (Obsidian CLI) is an optional accelerator for a single open
vault — never load-bearing.

When you discover something durable (architecture, a gotcha, a decision and its
why), write it back to the vault. **At session end**, offer `/vault recap`.

**Prompts publish with every recap.** Immediately after `/vault recap` writes
`vault/sessions/<name>.md`, run `scripts/export-prompts <name>` — it extracts
this session's user prompts from the Claude Code transcript (tool output,
system events, and skill expansions excluded; private data redacted inline) and
writes `vault/sessions/<name>-prompts.md` linking `[[<name>]]`. Add a
`[[<name>-prompts]]` link in the recap note. If it errors or reports a prompt
count implausibly low for the session, STOP and investigate (transcript-format
drift) — never publish an empty/thin export. Before committing prompt files,
check for glossary drift: every `/command` appearing in them must be in
config-history.md's glossary. The pair is the raw material for
the submission's curated `prompt-history.md`. Prompt exports are outward-facing
— the Public-repo hygiene scan applies before committing them.

## Docs layout

- `docs/` — generated documents: working notes, plans, analyses.
- `docs/reports/` — persistent, prepared deliverables meant to be kept/shared.
- `docs/logs/` — transient/ephemeral output of repeatable processes (gitignored).

## Skills available here

- `vault` — persistent Obsidian memory (orient, look up, write back).
- `gstack` — drive a real browser (`/browse`) to research, QA, and verify.
- `wargame` — stress-test a plan on paper before building it.
- `vet` — judge an idea's kernel: proceed / probe-first / kill.

**In-tree config mirror.** The machine-level config this repo runs under
(these skill bodies, the global hooks, global CLAUDE.md) is mirrored at
`.claude/` so a reviewer of this public repo can read it — see
`.claude/README.md` for the path cross-reference. The mirror is generated by
`scripts/sync-claude-mirror` (never hand-edit mirrored files); before
committing anything that touches config, run `scripts/sync-claude-mirror
--check` and refresh on drift.

## Rules of conduct

- **Durable over accurate — always.** Prefer references and constructs that survive
  commits, pushes, checkouts, moves, and machine changes over ones that are merely
  correct right now. This is a general principle, not just about paths:
  - **Paths**: relative, or derived at runtime (script location, `git rev-parse`,
    an env var with a computed default) — never hardcoded absolutes. A path that
    names `/home/<user>/...` or a specific mount breaks the moment the repo moves.
  - **Resume/cache keys**: content hashes, not mtimes (mtime resets on move, rsync,
    checkout). Identity, not incidental state.
  - **Config**: one source of truth others derive from, not the same literal copied
    to N places that then drift.
  - When durable and accurate genuinely conflict, make it durable and make the
    durable thing accurate — don't settle for a brittle literal.
- Be brief: no preamble, no recap of what the user knows, no surveying paths not taken.
- Idempotent, reversible-by-default; confirm before hard-to-undo or outward-facing actions.
- Report outcomes faithfully — if a step failed or was skipped, say so.
- Never `git push` (and never force-push) — the human pushes manually. A
  PreToolUse guard enforces this mechanically — registered globally
  (`~/bin/deny-git-push.sh`) and in-tree (`.claude/settings.json` →
  `.claude/bin/deny-git-push.sh`); this line is the why, not the enforcement.

## Public-repo hygiene (this repo is PUBLIC)

- **Scan before every commit.** After staging and before `git commit`, scan the
  staged diff (`git diff --cached`) for private data. Use `gitleaks protect --staged`
  if installed; otherwise grep the staged diff for, at minimum:
  - credentials: tokens, API keys, passwords, `Cookie:`/`Set-Cookie` values,
    session/CSRF IDs, private keys (`BEGIN … PRIVATE KEY`)
  - identity: email addresses, phone numbers, other people's names/handles
  - machine internals: absolute `/home/<user>/…` paths, hostnames, IPs,
    port/token pairs from local daemons (e.g. `.gstack/browse.json`)
  On any hit: do NOT commit; show the finding and let the user decide.
- **Never tracked, never force-added:** `course/` (paywalled curriculum),
  `.gstack/` (local daemon state incl. auth tokens), `vault/.obsidian/` UI state,
  `docs/logs/`. These are gitignored — treat the ignore as a hard rule, not a hint.
- **Prompt exports are outward-facing content.** Session-prompt files under
  `vault/sessions/` get the same scan before commit; redact hits inline
  (`[REDACTED: cookie]`) rather than dropping the whole prompt.
- Anything fetched from the authenticated community site beyond `course/`
  (names, posts, member content) must not enter tracked files.
