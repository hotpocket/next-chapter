# ADR 0007 — Repo-local `.claude/` mirror of the AI config

## Context
The `/conduct` init left this repo's docs and vault notes pointing at
machine-level config (`~/bin/claude-orient`, `~/.claude/skills/…`, global
hooks) that a Next Chapter reviewer cannot see. The public-repo wargame
([[2026-07-20 report|../../llm-docs/reports/2026-07-20_public-repo-and-legibility.md]])
had already flagged this as its dependency-inventory gap and an ELEPHANT
("reviewer must trust unverifiable process claims").

## Decision
- Mirror the config in-tree at `.claude/`: hook scripts (`bin/`), global
  conduct (`CLAUDE.global.md`), global hook registration
  (`settings.global.json`), and the bodies of the skills this repo runs
  (`skills/`: vault, wargame, vet, conduct, gstack slim).
- The mirror is **generated, never hand-edited**: `scripts/sync-claude-mirror`
  derives it from the global config (single source of truth — durable over
  accurate); `--check` exits non-zero on drift; tested by
  `scripts/test-sync-claude-mirror.sh` (red→green, 23 assertions).
- Two pieces are *live*, not just mirror: `.claude/skills/` load as project
  skills, and `.claude/settings.json` wires the push guard from the in-tree
  copy. Global-layer mirrors are named so Claude Code does NOT load them —
  double-registering the hooks would duplicate orientation/brevity injection.

## Exclusions (deliberate)
Skill `tests/` dirs (dogfood from other private projects); gstack beyond its
entry points (1.7 GB MIT upstream — SKILL.md, browse/SKILL.md, LICENSE,
VERSION only); learn-video + writing-great-skills (not used here);
`settings.local.json` (gitignored).

## Consequences
Reviewers cross-reference any machine path in notes/prompts via the table in
`.claude/README.md`. Config-touching commits must pass
`sync-claude-mirror --check`. The mirror is outward-facing content — the
public-repo hygiene scan applies (scanned clean at adoption: gitleaks + grep
for emails/absolute paths/handles).
