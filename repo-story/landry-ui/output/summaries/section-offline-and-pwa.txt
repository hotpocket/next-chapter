Chapter three covers taking a book offline and installing the player as an app. One honesty note governs it: the whole subsystem was built in an early-April twenty twenty-six burst, before this project exported prompts, so no verbatim prompt survives; every attribution paraphrases the commit trail and a detailed session note dated the third of April.

Four features. First, the per-book download button, downloadForOffline: one press caches the shell and every chapter sequentially, holding a screen wake lock and a refresh-confirmation guard, counting progress as it goes, and storing both full and summary tracks. Each chapter is its own cache entry keyed by absolute URL, so adding chapters never invalidates saved ones. Second, the service worker, sw dot js, with two deliberately separate caches: audiobook dash shell, network-first, for the app's files, and audiobook dash audio, cache-first, for chapters, so a code update never wipes downloaded audio. Third, offline seeking: a serveRange helper slices a cached whole file into two oh six byte-range responses using Blob dot slice rather than arrayBuffer, documented as the difference between twenty-second and instant seeks; a companion lesson says cache keys must be absolute URLs. The chapter also records two dead ends, an abandoned background-fetch API and tablet out-of-memory crashes, plus a legacy-cache eviction that recalls a bad chapter from listeners' devices. Fourth, the manifest that installs the player standalone, with its own name and icons.
