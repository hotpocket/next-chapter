Chapter four covers how the player is adopted by other projects, and how the tests prove it before it ships. The fetch mechanism is a shell script named luinst: given a component path and a destination, it shallow-clones the repository, then removes and recreates the destination and copies the component in. A fetch is a replacement, not a merge. It defaults to an HTTPS clone, with an environment variable to override to SSH. That default has verbatim provenance: the July twentieth session flipped the repository public, opening with "do an audit on landry-ui to see if it is safe to flip public," after which consumers no longer needed SSH keys.

The vanilla embed contract is a single RepoStoryPlayer init call taking a container, a books array, an audio base URL, a transcript URL, and a title. A React variant, the AudiobookPlayer component, is deliberately behind: still on the single-file audio model, missing the Full-versus-Summary toggle, reading mode, and offline. The transcription-error flag button is wired and styled but unreachable in vanilla, pending the feedback backend; only the React variant renders it.

Two small tools ship alongside: serve dot py, a Range-capable dev server for audio seeking, and check-m4b, a legacy validator for a format the player no longer consumes. Two Playwright suites, follow dot test and summary dot test, carry contracts A through M and A through G against an ffmpeg-built fixture. The summary suite exists because of a verbatim July twenty-first directive to test first and write code second.
