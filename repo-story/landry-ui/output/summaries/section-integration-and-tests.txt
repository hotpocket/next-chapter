Chapter four covers how the player gets adopted by other projects, and the tests that make it trustworthy. Adoption runs through luinst, a shell script that takes a component path and a destination directory, shallow-clones the repository, then deletes and recreates the destination and copies the component in. A fetch is a replacement, not a merge. It clones over HTTPS by default, a change with verbatim provenance: the July twentieth session flipped the repository public, opening with a prompt that asked Claude to "do an audit on landry-ui to see if it is safe to flip public," after which consumers no longer needed SSH keys. An environment variable restores the SSH form.

The vanilla embed contract is one RepoStoryPlayer init call taking a container, a books array, an audio base URL, a transcript URL, and a title. A React variant, AudiobookPlayer, is deliberately behind by recorded decision: still on the single-file audio model, missing the Full-versus-Summary toggle, reading mode, and offline support. The transcription-error flag button is wired and styled in vanilla but never rendered, pending the feedback backend; only the React variant shows it.

Tooling ships alongside: serve dot py, a Range-capable development server for audio seeking, and check-m4b, a legacy validator for a single-file format the player no longer consumes. Playwright suites, follow dot test and summary dot test, assert the follow, reading-mode, text-size, and summary behaviors against an ffmpeg-built fixture. The summary suite exists because of a verbatim July twenty-first directive: test first, write code second.
