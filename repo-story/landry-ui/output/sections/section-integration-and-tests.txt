Chapter four. Adopting the player, and trusting it.

Everything so far lives inside one repository. For any of it to matter, a consuming project has to pull a component out. That is the job of luinst, spelled l-u-i-n-s-t, a small shell script. It takes two arguments: the path of the component inside the repository, and the destination directory in the consuming project. It makes a temporary directory, shallow-clones the repository at a depth of one commit, and checks that the requested component path actually exists in the clone. Then comes the step consumers depend on: it deletes the destination directory outright, recreates it, and copies the component's contents in. A fetch is a replacement, not a merge. Nothing stale survives, and the destination always matches the repository exactly. The usual call pulls audiobook slash vanilla into a player directory, and consuming projects gitignore that directory, because the fetch is the source of truth.

The clone happens over HTTPS by default, and that default has a date. It comes from the July twentieth session, the session that flipped this repository from private to public. The prompt that opened that work read: "this repo will serve the site. do an audit on landry-ui to see if it is safe to flip public. wargame that audit to have as much confidence in the analysis as possible." When the audit passed, the follow-up was short: "run the gh flip command yourself." With the repository public, consumers no longer need SSH keys to clone it, so luinst's default moved to HTTPS the same day. A later prompt in that session cleaned up the documentation: "use my voice, that is fine. fix luinst https path in docs. then drop them from the todo in the session recap." The SSH form still works, through the LANDRY underscore UI underscore REPO environment variable.

Next, what the host page does with the fetched player. The vanilla embed contract is three tags and one call. A stylesheet link to player dot css. A script tag for feedback dot js, loaded before player dot js. Then a call to RepoStoryPlayer dot init with an options object: a container element, which is required; a books array; an audioBaseUrl that defaults to "audio slash"; a transcriptUrl; a feedbackUrl; and a title for the library heading. Point those at real data and the player runs.

The repository also ships a React variant, a TypeScript and Tailwind component called AudiobookPlayer, and it is deliberately behind the vanilla player. That is a recorded decision, not a captured prompt. The session note from early April gives the reasoning as vanilla JavaScript over React for the canonical player, more portable, no build step, and describes the React version as feature-complete but not yet optimized like vanilla. In practice the React variant still runs the old single-file audio model: one audio element, seeking by chapter start-second offsets, where vanilla loads a separate file per chapter. It has no Full-versus-Summary toggle, no reading mode, no text-size stepper, no offline download. It does have arrow-key seeking of ten seconds either way, which vanilla lacks. It is the older cousin, kept working and left behind on purpose.

One control splits the two variants: the flag button, which a listener taps to report a bad transcription. The React variant renders it, a warning glyph that turns red when flagged and posts a payload naming the project as repo-story, the type as transcription-error, and carrying the book slug, chapter index, chunk index, chunk text, and timestamp. The vanilla player does not render it at all. The wiring is fully present: feedback dot js defines flag, unflag, and is-flagged; the init call starts the feedback module; the chunk-flag styling sits in the stylesheet in red. But player dot js never draws the button and never calls those functions, so in vanilla the feature is wired, styled, and unreachable. That gap is deliberate for now. The April session note keeps it as a to-do: feedback flagging UI removed, re-add when the backend is deployed.

Development tooling sits alongside. Serve dot py is a threaded development server that exists because Python's built-in file server does not honor Range requests, and audio seeking needs them. It parses a byte range, answers with a 206 partial-content response and the correct Content-Range header, and streams the file in sixty-four-kilobyte chunks. Check-m4b, a Python script with no file extension, is a validator from an older architecture. It checks that a single-file M4B has its moov atom at the front for fast starting, printing the exact ffmpeg fix command when it does not, then checks for an AAC codec, for chapters, and for a positive duration. The shipped player consumes per-chapter M4A files now, so check-m4b validates a build path the player no longer takes. It stays in the repository as a legacy tool.

Last, the tests. The suites are Node ES-module scripts driving Playwright, the browser-automation library, resolved from a local pinned copy. Follow dot test dot m-j-s carries contracts covering follow-scroll, reading mode, the text-size stepper, the track bar, and the scrollbars. It was written across the un-exported July sixteenth and seventeenth push, committed alongside each feature, so its provenance is the commits rather than a captured prompt. Summary dot test dot m-j-s carries the Full-versus-Summary contracts and has a verbatim anchor. The July twenty-first session that built the Full-versus-Summary toggle opened with the user invoking the house rule. The prompt read: "you see your directives to test first write code second right?" That directive is why the summary contracts exist as a suite rather than an afterthought. The contracts check concrete behavior: switching to Summary loads the summary M4A and shows chunks that start with the words "Summary one"; the total time reads twelve seconds; clicking the third summary chunk moves the clock to about three seconds; summary mode survives a page reload; and a book with no summaries hides the toggle entirely. Both suites run against a fixture built by gen dot s-h, which uses ffmpeg to generate silent audio chapters and a synthetic transcript, one book with summaries and one without, precisely to exercise that last branch.

That closes the book. This player, the vanilla one, fetched by luinst into the trilogy site, is the one playing this sentence right now.
