This is repo-story: the Claude Code skill and the Python scripts that turned each of these repositories into the audiobook you are hearing. This chapter walks the skill itself. The two after it walk the build scripts that make the audio, and the last walks the tests and the provenance record behind everything.

The skill is a pipeline of five phases, and that shape is the one invariant: Survey, Explore, Inventory, Research, Narrate. Survey reads the repository's README, its manifest files, and its git remote, then presents a short catalog — project name, author, purpose, tech stack, and how much prompt provenance exists. Explore launches one explorer agent per repository; each catalogs every user-visible feature — exact commands, exact paths, exact defaults — and writes a dossier, one markdown file per repo, into a folder named dossiers. Inventory reads the dossiers and groups the features into chapters, orientation first, core workflow next, supporting features after, and writes the plan to inventory dot m d. Research runs per chapter: a code-researcher agent re-verifies current behavior against the source, a prompt-researcher agent traces each feature to the prompts that shaped it, and both write packets into a folder named research. Narrate writes beats, then sections, then summaries, and finally chapters dot t x t — one section filename per line. That last file sets the order of the audio you are hearing.

The skill exists because of one prompt. In the July twenty-first vendoring session the user re-pasted his own pre-project plan, calling it the kernel of the journey, and the session export preserves it verbatim: "Create a system for turning a github repo into a podcast. It will explore the content in the repo for: history and core concepts. The prose generated will generated for a tts engine and will follow a historical arc and also talk about how this repo adds to the historical arc." The same prompt defined the smallest acceptable version: "A process you can hand to an AI with a github url that will produce a reasonably small number of chapters that I can read online." And, answering a separate question in the same plan: "A prompt and an audio output." A repo URL in, chaptered audio out — that is the seed. Hold on to the phrase historical arc, because the skill as it runs today has deliberately reversed it, and this chapter ends with how.

The pipeline splits work across two models by kind: prose runs on Fable, code and research run on Opus. The main session is pinned to Fable and owns the planning phases: survey, inventory, beats, chapter ordering. Spawned work goes through four named agents in the dot claude agents folder. Three pin Opus for exploration and research: the explorer, the code-researcher, and the prompt-researcher. The fourth, the narrator, pins Fable, because narration is the one phase judged purely as prose, heard once, with no re-reading. The split is structural, not prose. The settings file pins the session — model fable, effort level x high, attested by the decision records and recaps, not any surviving prompt — and each agent file pins its model in its frontmatter. Two decision records carry the history. The first, zero zero zero one, titled Fable plans, Opus executes, drew the line by tier: Fable planned as the strongest synthesizer, and everything spawned ran on Opus because prose volume at Fable prices was not worth it. It also records rejecting inline use-model-X instructions, because prose drifts. The live record, zero zero zero two, titled Fable writes, Opus researches, supersedes it: the model generation turned over — Opus became the stronger reasoner and Fable the stronger writer — the assignment moved; the enforcement never changed. Failure stays loud: if either model is unavailable, sessions fail at the pin rather than silently falling back.

Each agent is narrowed to its job in its own file. The explorer is told, verbatim, do not chase lineage or philosophy. The code-researcher re-reads the source and corrects earlier exploration errors silently. The prompt-researcher is told never to blur its three labels — verbatim, paraphrase, or inference. The narrator gets only reading and writing tools, no shell and no search, because its only job is prose. These four were not always these four: the July tenth recap names the set as explorer, code-researcher, history-researcher, and narrator, and the history-researcher — which once ran web searches for historical context — was later deleted and replaced by the prompt-researcher.

One artifact carries the handoff from planning to narration: the beats. The project glossary defines them as exactly that. For each chapter the main session, on Fable, writes a beats file — feature order, must-hit details pointing into the research packets, prompt citations, one-clause transitions — and a narrator agent — today on Fable — expands it into a section. This replaced an older rule that let Fable narrate small books inline; the first decision record lists that two-to-four-themes, write-inline approach among its rejected options, replaced so planning context reaches the narration through beats rather than inline prose.

The whole pipeline also runs unattended, under a contract in a file named AUTORUN dot m d. In its own words, the plan file is the thinking and AUTORUN is the doing. It takes a GitHub repository URL, looks for prompt provenance in known locations, and works inside one top-level folder per run, named after the repo. The build scripts default their outputs relative to the working directory, so changing into that folder makes every default just work, with no override flags. Its constraints are firm. No SSH commands. No publishing without an explicit ask, because publishing is the user's own git push. Never clobber a prior run. Honor the model split, with the same loud failure. And never pause mid-pipeline for approval — AUTORUN overrides that to present and continue.

Now the reversal of the historical arc. It took two attempts. On July tenth the user tried a sentence-level de-fluff pass, in an understated reportage register, across the finished sections of an earlier run. The recap records it as reviewed and rejected — it made the content drier without fixing the fluff — and fully rolled back, with the note that future tone work belonged at the beats level, not in word pruning. The fix that stuck came on July twenty-second, and it changed the methodology rather than the wording. That prompt survives verbatim. It opens, "the story seems long winded, and a bit too fantastical," says the long form "imposed too much on the readers time, the reader being the reviewer," and lands on the redirect: what the user wanted was "a walkthrough of the features and the prompts that influenced the features as they currently exist." That prompt is the single largest shaper of what you are hearing. The skill's description became audio walkthroughs of features and the prompts that shaped them. The history-researcher was deleted and the prompt-researcher put in its place. And the narrate brief gained a paragraph test banning scenic openings, extended analogies, and historical lineage — the rewrite of the prompts folder that produced this very section.

Those phases end with text files. Turning text into a voice is the next chapter.
