This is repo-story: the Claude Code skill and the Python scripts that turned each of these repositories into the audiobook you are hearing. This chapter walks the skill itself. The next two walk the build scripts that make the audio, and the last walks its tests and the provenance behind it all.

The skill is a pipeline of five phases, and the pipeline is the invariant. Survey, then Explore, then Inventory, then Research, then Narrate. Survey reads the repository's README and its manifest files and its git remote, then presents a short catalog: project name, author, purpose, tech stack, and how much prompt provenance it can find. Explore launches one explorer agent per repository to catalog every user-visible feature — exact commands, exact paths, exact defaults — and writes a dossier, one markdown file per repo, into a folder named dossiers. Inventory reads all those dossiers and groups the features into chapters, orientation first, core workflow next, and writes the plan to a file named inventory dot m d. Research launches, per chapter, a code-researcher agent that re-verifies current behavior and a prompt-researcher agent that traces each feature to the prompt that shaped it, and writes packets into a folder named research. Narrate writes beats, then sections, then summaries, and finally a file named chapters dot t x t that lists one section filename per line. That file drives the order of the audio you are hearing.

The skill exists because of a single prompt. In the July twenty-first vendoring session, the user re-pasted his own pre-project plan and called it the kernel of the journey. Verbatim, it read: "Create a system for turning a github repo into a podcast. It will explore the content in the repo for: history and core concepts. The prose generated will generated for a tts engine and will follow a historical arc and also talk about how this repo adds to the historical arc." The same prompt named the smallest version: "A process you can hand to an AI with a github url that will produce a reasonably small number of chapters that I can read online. A prompt and an audio output." A repo URL in, chaptered audio out — that is the seed. Note the words "historical arc." The skill you are hearing has deliberately reversed that framing, and I will return to how.

The skill runs on a deliberate split between two models. The main session is pinned to Fable, a Claude model used here as the planner, and it does the planning phases: the survey, the inventory, the beats, and the chapter ordering. The execution phases run only through four named agents, each pinned to Opus, another Claude model used here as the executor. The four are the explorer, the code-researcher, the prompt-researcher, and the narrator. This split is not prose that asks nicely — it is structural. The settings file pins the session with a two-key object: model, fable; effort level, x-high. That is a paraphrase of the pin, drawn from the decision record and the recaps. Each agent file pins its own model to opus in its frontmatter. The decision is recorded in the first architecture decision record, numbered zero-zero-zero-one, titled "Fable plans, Opus executes." Its reasoning, quoted from the record: "Fable is the strongest synthesizer but the wrong price for the token-heavy execution phases; Opus is the strongest generally-priced executor." The record also keeps what it rejected — inline "use model X" instructions scattered across roughly six places in the prose, rejected because prose drifts and relies on the orchestrator obeying it every run. Structural pins were chosen over prose. And the failure mode is loud by design: if Fable is unavailable, sessions in this repo fail at the model pin rather than silently falling back.

Each of the four agents is narrowed to its job. The explorer is told, in its own file, "do not chase lineage or philosophy." The code-researcher re-reads the source and corrects earlier exploration errors silently. The prompt-researcher traces each feature to its prompts and is told "never blur the labels." And the narrator's tools are deliberately cut to reading and writing — no shell, no search — because its only job is prose. These four were not always these four. A July tenth recap names the set as explorer, code-researcher, history-researcher, and narrator; the history-researcher, which once ran web searches for historical context, was deleted and replaced by the prompt-researcher.

Between planning and narration sits one handoff artifact: the beats. The project's glossary defines beats as exactly that — the handoff from planning to narration. For each chapter, the main session on Fable writes a beats file: feature order, the must-hit details pointing at the research packets, the prompt citations, and one-clause transitions. Then a narrator agent on Opus expands those beats into a section. This structure replaced an older rule where Fable narrated small books inline. The decision record lists that "two-to-four themes, write inline" approach among its rejected options, replaced so the planning context reaches the narration without paying Fable's price for the volume of prose.

The whole pipeline can also run unattended, and that contract lives in a file named AUTORUN dot m d. As the file itself puts it, the plan is the thinking and AUTORUN is the doing. It takes a GitHub repository URL, finds prompt provenance in known locations, and works inside one folder per run named after the repo — so that when the build scripts default to their output paths, changing into that folder makes every default just work with no override flags. Its constraints are firm: no SSH commands; do not publish without an explicit ask, because publishing is the user's own git push; do not clobber prior runs; honor the model split with loud failure; and do not pause mid-pipeline — AUTORUN overrides that to present-and-continue.

Now, that reversal of the founding "historical arc." It came in two moves. On July tenth, the user tried to fix perceived fluff with a sentence-level de-fluff pass in an "understated reportage" register across finished sections. The recap records that it was reviewed and rejected — it made the content drier without fixing the fluff — and fully rolled back, with a note that any future tone work should happen at the beats level, not by pruning words. The real fix came on July twenty-second, and it changed the methodology rather than the wording. Verbatim, the prompt read: "the story seems long winded, and a bit too fantastical. I don't so much as want to provide a historical account as I want to provide a walkthrough of the features and the prompts that influenced the features as they currently exist." That single prompt is the largest shaper of the chapter you are hearing. The skill's description became "produce audio walkthroughs of their features and the prompts that shaped them." The history-researcher agent was deleted and the prompt-researcher put in its place. The narrate brief grew a paragraph test that bans scenic openings, extended analogies, and historical lineage. That rewrite of the prompts folder is what produced this very section.

Those phases all end with text files. Turning text into a voice is the next chapter.
