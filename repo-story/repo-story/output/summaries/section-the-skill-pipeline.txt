This chapter walks repo-story itself: the Claude Code skill that reads a repository and writes the walkthrough you are hearing. A repo URL goes in, chaptered audio comes out — a shape set by a founding prompt that called it turning a github repo into a podcast.

The skill runs five phases whose order never changes: Survey, Explore, Inventory, Research, Narrate. Survey catalogs the project. Explore writes a dossier of features per repo. Inventory groups features into chapters. Research verifies the code and traces each feature to its prompt. Narrate writes the sections and summaries, then a chapters file that sets the audio order.

Underneath is a model split, recorded in architecture decision record zero-zero-zero-one: the main session is pinned to Fable for planning, and four named agents — explorer, code-researcher, prompt-researcher, narrator — are pinned to Opus for execution. The pins are structural so the rule can't drift, and the session fails loudly if Fable is unavailable. Between planning and narration sits the beats file, the handoff artifact. A separate file, AUTORUN.md, is the unattended contract for full runs.

Prompts drove all of it, most visibly a July twenty-second redirect: the user asked for a walkthrough of the features and the prompts that shaped them rather than a historical account. That prompt deleted the old history-researcher, added the prompt-researcher, and produced the very methodology this chapter follows.
