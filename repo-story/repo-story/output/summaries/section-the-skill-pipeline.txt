This chapter walks repo-story itself: the Claude Code skill that reads a repository and writes the walkthrough you are hearing. A repo URL goes in and chaptered audio comes out — a shape set by a founding prompt that called it turning a github repo into a podcast.

The skill runs five phases in a fixed order: Survey, Explore, Inventory, Research, Narrate. Survey catalogs the project. Explore writes a dossier of user-visible features per repo. Inventory groups the features into chapters. Research verifies current behavior and traces each feature to its prompts. Narrate writes beats, sections, and summaries, then a chapters file that sets the audio order.

Underneath sits a model split, governed today by architecture decision record zero zero zero two, Fable writes, Opus researches: the main session and the narrator agent run on Fable, the writing model, while the explorer, code-researcher, and prompt-researcher agents run on Opus for exploration and research. The pins are structural so the rule cannot drift, and a session fails loudly if either model is unavailable. Beats are the handoff artifact between planning and narration, and a file named AUTORUN dot m d is the contract for unattended runs.

Prompts steered all of it, most visibly a July twenty-second redirect asking for a walkthrough of the features and the prompts that shaped them instead of a historical account — the change that deleted the history-researcher, added the prompt-researcher, and produced the methodology this chapter follows.
