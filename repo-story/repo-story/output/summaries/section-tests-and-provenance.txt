This last part is the proof and the paper trail: how repo-story tests itself, and how this copy came to live, scrubbed, inside its parent project.

The tests come first by written rule — the July twenty-first prompt reads, test first, write code second — and the suites are self-contained scripts run by hand, no continuous-integration server. Test build book is the bash suite over staging and preflight: sorted chapter order, the numeric prefix strip, verbatim copy, a broken Python environment stopping the build early. Test build m4a is the summary-track regression: change only the summary and the manifest version hash must change. Test build site guards the favicon link and the feedback-URL wiring a vendor scrub once dropped. Test build audio pins the content-addressed chunk cache: same text, voice, and parameters give the same key, and editing one sentence changes exactly one. Test chunk cache proves the migrate and garbage-collect commands: a legacy index-named cache becomes content-addressed without re-rendering, and orphaned chunks are swept.

The provenance is the heart of it. A script replays the private repo's history commit by commit, each commit carrying a Replayed-From trailer and its original author date; an Amazon Web Services deploy path and personal details are excluded, redactions left as bracketed placeholders. Verbatim prompts drive it all — scrub before public, replay with exclusions, redact prompts rather than delete. Twenty-three trailers verify in the live git log, and this scrubbed, tested copy is the pipeline that produced the audio you are hearing.
