This last part is the proof and the paper trail: how repo-story tests itself, and how this copy came to live scrubbed inside its parent project.

The tests come first by written rule. From the July twenty-first session: test first, write code second. Every feature ships with a guard, and the suites are three self-contained scripts run by hand, with no continuous-integration server. Test build book is a bash suite of eighteen checks over staging and preflight — sorted order, the numeric prefix strip, the markdown-to-text rewrite, per-chapter cache invalidation, and a broken Python environment stopping the build early. Test build m4a is the summary-track regression: change only the summary and the manifest version hash must change. Test build site guards the favicon link and the feedback-URL argument, the latter because a vendor scrub once dropped the wiring and crashed every build.

The provenance is the heart of it. A script replays the private repo's history commit by commit, each carrying a Replayed-From trailer and its original author date; an Amazon Web Services deploy path and personal details are excluded, redactions left as bracketed placeholders. Verbatim prompts drive all of it — the scrub-before-public decision, the replay-with-exclusions order, and the rule that prompts get redacted, not deleted. Twenty-three trailers verify in the live git log. And this scrubbed, tested copy is not a description of the pipeline; it is the pipeline that produced the audio you have been hearing.
