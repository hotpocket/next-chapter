This part of the artifact turns generated audio into a playable, publishable site. build_transcripts.py produces the read-along: it re-runs the same chunking the audio used, recomputes each chunk WAV's content-addressed name through the audio builder's own helpers — reading voice and speech parameters from a cache-params.json sidecar the render wrote — probes each WAV for its duration, and writes transcripts.json with chapter-relative timestamps, plus a summary_chunks timeline for each chapter's short version. build_site.py assembles the standalone site: it copies per-chapter audio, prunes stale files, carries an optional feedback-url flag, and links a favicon. luinst fetches the player from landry-ui, a separate component repository, into a gitignored player directory. build_book.sh is the one-command builder: a folder of chapter text in, a standalone emailable site out, transcripts inlined so no server is needed. Two small servers, serve.py and serve_chunks.py, give range-capable local preview and a live network playlist of raw chunks. Publishing has exactly one target: the parent next-chapter repository's GitHub Pages folder — no cloud hosting, no deploy scripts, the owner pushes.

Prompts drove the sharp edges. The July twenty-first sessions fixed the summary time display, corrected the favicon in two steps, insisted on a no-server local build, and retargeted publishing away from cloud hosting — all verbatim in the record.
