The closing chapter covers the configuration and memory the sessions ran under, made readable to a reviewer who was never at the keyboard.

The centerpiece is the in-tree dot-claude mirror: checked-in copies of the machine-level config the agent was actually running, so paths referenced in vault notes and prompt exports resolve to real files a reviewer can read. The script scripts slash sync-claude-mirror generates it from the global config, the single source of truth. It pulls the orientation hook, the live push-guard script, the global conduct file and settings, and four full skills, with the large gstack browser skill allowlisted to entry points only. Its roots are environment-derived rather than hardcoded, it fails loudly on a missing source, and a check mode acts as a drift gate before any config commit. Two things stay live here, the settings hook and the skills; the rest is documentation-only, deliberately unregistered so the global hooks don't double-fire. A tests-first companion suite exercises it against a fake global directory across six phases.

For memory, a session-start hook prints three pointer lines, latest recap, open todos, open probes, and delegates reading to vault-digest, a headless grep-and-awk tool. The vault holds four session recap-and-prompt pairs, todos, projects, a vet, and nine architecture decision records, superseded ones kept on purpose after an audit for reviewer legibility.

One verbatim prompt from the July twentieth config-mirror session drives the whole mirror; its durability properties are the project's standing rules applied. With that, the build is auditable end to end.
