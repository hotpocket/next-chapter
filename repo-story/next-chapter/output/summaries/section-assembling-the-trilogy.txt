This chapter is the assembly: how three separate pipeline runs become the published site the player loads. The registry, scripts slash trilogy dot json, is the plan in data form — a title, a favicon, an optional analytics key, and three books, each with slug, manifest, transcripts file, and description, pointing into pipeline run folders. The assembler, scripts slash build dash trilogy dash site, reads that registry and converts each manifest with one function imported from the pipeline's own code rather than reimplemented. It copies audio with a size-compare skip and stale-file pruning, prefixes filenames with each book's slug, merges all transcripts into one file cache-busted by the first eight characters of its content hash, and generates index dot html with the books inlined. It emits an analytics tag only when the registry asks, and patches the copied service worker so cross-origin requests bypass its caching, else the analytics beacon's per-hit URLs would flood it with quota-padded opaque entries.

Its sharpest rule is provenance: it pins an exact commit for the player only when the player directory is a real checkout of the external landry-ui project — pinning any enclosing repo's HEAD would be, in the code's words, provenance theater. That fix is frozen as a negative assertion in the test file, which exists because a prompt enforced test-first discipline. The vendored generator brought the pipeline in as scrubbed, replayed history. Nothing here deploys — the owner pushes, a hook enforces it — the stance the prompts get next.
