This repo publishes not just the code but the prompts that made it. Every user message from every session is exported verbatim and shipped alongside the code. The curated index, prompt-history.md, carries the running total, and that total agrees with the export files by construction, not by coincidence.

The tool that produces those exports is a bash script named export-prompts. You give it a session name, and it finds the newest Claude Code transcript for this repository, reads it, and writes a companion file next to that session's recap. It keeps only the user's messages. Everything else is dropped: the assistant's replies, tool results, system notifications, and the skill-expansion blocks that appear when a slash command loads its instructions. Concretely, the extraction selects records of type user, and when a message's content is an array that contains a tool result, it drops the whole message rather than risk leaking tool output into the record. Then it filters by prefix: a prompt is thrown out if it begins with a system-notification marker, a task-notification tag, a system-reminder tag, a local-command tag, or the line that starts a skill body. Empty prompts go too. What survives is the human half of the conversation and nothing else.

Before any of that is written, each surviving prompt passes through inline redaction. The rule here is that the value is replaced but the line survives, so the prompt stays readable and its shape is preserved. An email address becomes the token redacted-email. Anything that looks like a cookie, an authorization header, or a CSRF token becomes redacted-credential. A private-key header becomes redacted-private-key. Strings that match known API-token shapes become redacted-token. And any home-directory path is collapsed to a tilde, so no machine's internal layout ships in a prompt. All of this exists because of a single prompt from the July twentieth foundation session. It read, verbatim: "ok, this will be a public repo. add scanning verbage to the claude.md to ensure no private data leeks into commits. Along with this I will want to be publishing the prompts alongside each session note that is captured with a slash vault recap." That one message seeds both the hygiene rules and the export pipeline. The build order came a few prompts later, just as verbatim: "installed, build export-prompts and wire it in." The foundation recap records the result as the script plus eleven tests, written test-first, red to green.

The export writes frontmatter tagging the file as type prompts, a header noting that tool output and system events are excluded and private data is redacted inline, and then each prompt numbered in sequence. After it writes, if the leak-scanner gitleaks is on the path, it runs it against the output file and warns, but never blocks, if anything is flagged.

There is one more rule around the count, and it was earned rather than designed. The instruction now standing in the project's CLAUDE.md is that an implausibly low prompt count means the transcript format has drifted, and the correct response is to stop and investigate rather than publish a thin export. This rule exists because of a real miss. On July twenty-first, the counts were wrong: background task-notification blocks had been counted as prompts, inflating earlier numbers. When the extractor learned to exclude those blocks, the foundation session's count fell from fifty-seven to forty-six, and the vendored session's rose from twenty-one to twenty-seven as other fixes landed. All four exports were regenerated clean. The trigger for the whole chain was a sanity-check prompt from the July twenty-first vendored session: "we are persisting the prompts, but not any of the responses. do the requirements want us to preserve the responses from the AI also?" The old pre-fix recap line still shows the stale fifty-seven, left in place on purpose so the correction stays auditable.

Next, the tests. A script named test-export-prompts.sh runs the exporter against a tiny fixture transcript, carrying one assertion for every rule the exporter enforces and gaining another each time a new way of leaking non-prompt content turns up. Two of them are the load-bearing ones: a tool result in the fixture must not appear in the output, and a home path written as the string slash home slash testuser must be redacted to a tilde. The fixture also carries a planted email address so the test can confirm redaction fires. That email is there because the public-repo wargame from the foundation session caught a real address in the author's own test fixture. The recap's phrasing was that fixtures are leak surface too, and that finding is why the redaction assertions exist at all.

The prompts do not just ship raw. The README carries a Sessions and prompts table, one row per session linking the recap to its prompt export with the count beside it. That table traces to a July twenty-first instruction, verbatim: "ensure the links to prompts are on the readme. and include any links to resources there ... so the reviewer can navigate easily." Behind it sits an earlier foundation prompt asking what mechanism gives the reviewer, quote, "an unambigous breadcrumb trail to follow of how I am building this." The count beside each row is not maintained by hand. A gate named check-session-wrapup finds the newest session in the vault's Session Log and re-derives every published count from the exports themselves. The Session Log row has to agree with the README table and its totals line, and so do the curated index and the command glossary. Nothing is checked against a copied literal, because a number nobody re-derives is a number that quietly goes wrong. It exists because a July thirtieth recap shipped with the curated index left un-updated, and the instruction that followed asked for the rest of the missed dependencies too, verbatim: "add them as checks to the wrap up process so they don't get missed again." The curated map over the raw exports is prompt-history.md, and a decoder document, config-history.md, explains the tools and slash commands the prompts invoke. A standing rule requires that every slash command appearing in an export already be defined in that file's glossary before publish, so a reviewer never meets an unexplained command.

All of this is wrapped in hygiene. Before every commit, the staged diff is scanned, by gitleaks or by grep, across three classes: credentials, identity, and machine internals. That rule traces to the same July twentieth public-repo prompt and a follow-up asking to wargame the strategy for securing a public repo. On top of it sits a private token-map scan for identifiers a regular expression cannot catch. That second scan exists because of the July twenty-first lesson, told straight: quoted agent output inside prompt exports had leaked infrastructure identifiers and family names past gitleaks and into pushed history. The prompt that met it was verbatim: "this is still private and we can force push to rewrite the remote history. this does expose that we need to scan our prompts also as a source of private data leakage." It was fixed by a full-history rewrite while the repo was still private, and turned into a new standing rule that checks every staged diff and every prompt export against a gitignored banned-token list.

Prompts are half the audit trail. The config they ran under is the other half, and that is the last chapter.
