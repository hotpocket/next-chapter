This repo publishes not just the code but the prompts that made it. Every session's user prompts are exported verbatim and shipped alongside that session's recap, and a curated index, prompt-history.md, maps the whole set. Every count those pages claim is re-derived from the export files themselves, so the numbers agree by construction, not by coincidence.

The tool that produces the exports is a bash script named export-prompts. Given a session name, it finds the newest Claude Code transcript for this repository and writes a companion file beside that session's recap in the vault. It keeps only what the human typed. The extraction selects records of type user; if a message's content array contains a tool result, the whole message is dropped rather than risk leaking tool output. Prefix filters then throw out anything that begins with a system-notification marker, a task-notification tag, a system-reminder tag, a local-command tag, or the line that opens a skill body. Empty prompts go too.

One filter is newer than the rest. The script also drops any transcript record flagged isMeta, the marker on user-role records the harness injected itself. That flag closes a real gap: skill bodies loaded by the Skill tool carry no base-directory prefix line, so the older prefix filter missed them, and thousands of lines of skill text once landed in an export as if they were a prompt. What the human typed is never flagged isMeta, so slash-command invocations survive in the trail. That fix landed on July thirtieth.

Each surviving prompt then passes through inline redaction. The value is replaced but the line survives, so the prompt stays readable. An email address becomes a redacted-email marker. Cookies, authorization headers, and CSRF tokens become redacted-credential. A private-key header and anything shaped like a known API token get markers of their own, and every home-directory path collapses to a tilde. The finished file carries frontmatter typing it as prompts, a header noting the exclusions and the redaction, and each prompt numbered in sequence. After writing, if the leak scanner gitleaks is on the path, the script runs it over the file and warns, never blocks, on a hit.

All of this exists because of a single prompt from the July twentieth foundation session. It read, verbatim: "ok, this will be a public repo. add scanning verbage to the claude.md to ensure no private data leeks into commits. Along with this I will want to be publishing the prompts alongside each session note that is captured with a slash vault recap." That one message seeds both the hygiene rules and the export pipeline. The build order came a few prompts later, just as verbatim: "installed, build export-prompts and wire it in." The foundation recap records the result as the script plus eleven tests, written test-first, red to green.

There is one more rule around the count, and it was earned rather than designed. The project's CLAUDE.md says an implausibly low prompt count means the transcript format has drifted, so stop and investigate rather than publish a thin export. The rule exists because of a real miss. On July twenty-first the counts were wrong: background task-notification blocks had been counted as prompts. When the extractor learned to exclude those blocks, the foundation session's count fell from fifty-seven to forty-six, and the vendored session's rose from twenty-one to twenty-seven as other fixes landed. The exports were regenerated clean across the board. The trigger was a sanity-check prompt from the same day's vendored session: "we are persisting the prompts, but not any of the responses. do the requirements want us to preserve the responses from the AI also?" The old pre-fix recap line still shows the stale fifty-seven, left in place so the correction stays auditable.

Next, the tests. A script named test-export-prompts.sh runs the exporter against a tiny fixture transcript, one assertion for every rule the exporter enforces, gaining another whenever a new way of leaking non-prompt content turns up. Two are load-bearing: a tool result planted in the fixture must not appear in the output, and a home path written as slash home slash testuser must be redacted to a tilde. The fixture also plants an email address so the test can confirm redaction fires. That email is there because the public-repo wargame from the foundation session caught a real address in the author's own test fixture. The recap's phrasing was that fixtures are leak surface too; that finding is why the redaction assertions exist.

The prompts do not ship raw and unindexed. The README carries a Sessions and prompts table, one row per session, each linking the recap to its export with the prompt count beside it. The table traces to a July twenty-first instruction, verbatim: "ensure the links to prompts are on the readme. and include any links to resources there ... so the reviewer can navigate easily." Behind it sits an earlier foundation prompt asking what mechanism gives the reviewer, quote, "an unambigous breadcrumb trail to follow of how I am building this." Above the raw exports sits prompt-history.md, the curated index, and beside it config-history.md, the decoder document whose command glossary must already define every slash command an export invokes before it publishes, so a reviewer never meets an unexplained command.

None of those pages is kept correct by hand. A gate named check-session-wrapup starts from the newest session named in the vault's Session Log and re-derives every published prompt count by counting prompts in the export files themselves, never by comparing one copied number against another. It confirms the recap and the export exist and link each other, that the session's counts and a matching totals line appear in the README, the same in prompt-history.md, and that every slash command the new export uses has its entry in the glossary. Any disagreement fails the gate, one line per problem. The gate exists because a July thirtieth recap shipped with prompt-history.md, the curated index, left un-updated. The instruction that followed asked, verbatim, to "add them as checks to the wrap up process so they don't get missed again."

All of this is wrapped in hygiene. Before every commit, the staged diff is scanned, by gitleaks or by grep, across three classes: credentials, identity, and machine internals. That rule traces to the same July twentieth public-repo prompt and to a follow-up asking to wargame the strategy for securing a public repo. On top of it sits a private token-map scan for identifiers a regular expression cannot catch. That second scan exists because of a July twenty-first lesson, told straight: quoted agent output inside prompt exports had leaked infrastructure identifiers and family names past gitleaks and into pushed history. The prompt that met it was verbatim: "this is still private and we can force push to rewrite the remote history. this does expose that we need to scan our prompts also as a source of private data leakage." The fix was a full-history rewrite while the repo was still private, and a new standing rule that checks every staged diff and every prompt export against a gitignored banned-token list.

Prompts are half the audit trail. The config they ran under is the other half, and that is the last chapter.
